# HostAliases RFC1123过滤与节点组交互超时设计

## 目标

- 节点组业务规划菜单和管理员自定义输入的单次等待时间由30秒调整为300秒。
- `/etc/hosts` 中任意非法主机名都不能导致探测Deployment被Kubernetes API整体拒绝。
- 可无损处理的大写DNS名称转成小写；无法可靠处理的名称整条丢弃并WARN，不猜测或删除部分字符生成新名称。

## Hostname处理

每个hosts别名单独处理：

1. 保留原值用于日志。
2. 将ASCII大写字母转换为小写；如发生转换，打印原值和新值。
3. 对转换结果执行RFC1123 subdomain校验：
   - 总长度1至253；
   - 不允许开头/结尾`.`或连续`.`；
   - 按`.`拆分的每段长度1至63；
   - 每段只允许`a-z`、`0-9`、`-`；
   - 每段必须以字母或数字开头、结束。
4. 校验失败只丢弃当前别名并WARN；同一行其他合法别名继续生成。
5. 使用规范化后的小写名称做去重和跨IP冲突检测，冲突时保留首次映射。

回环IP、localhost及非法IP继续沿用已有过滤逻辑。

## 超时

`NODEPOOL_PLAN_INPUT_TIMEOUT`固定为300秒。首次业务规划选择和选择5后的自定义输入共用该值；任一输入等待超时后立即WARN并回退云厂商默认规划。

## 验收

- 小写合法名称原样保留。
- 大写合法名称转小写并生成合法YAML。
- 大小写折叠后的重复去重、跨IP冲突保留首次。
- 下划线、连续点、首尾横线、首尾点、标签超过63、总长超过253均被丢弃并WARN。
- 同一IP行中非法别名不影响合法别名。
- 生成物料不包含任何非法主机名。
- 节点组两个输入提示均使用300秒。
