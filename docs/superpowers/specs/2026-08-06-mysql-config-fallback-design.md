# MySQL 配置文件优先级与历史环境回退设计

## 背景

通用 K8S 可用性检查当前仅从 `/data/home/ta/base_server_ta/application.yml` 提取非注释的 `jdbc:mysql://` 地址。部分未升级的历史环境没有该标准文件，但存在 `/data/home/ta/data_etl_ta/application.yml`，其中可从 `spring.datasource.url`、`hive.mysql.url` 等 JDBC URL 获取 MySQL 测试目标。

## 目标

- 标准配置优先；只有标准文件不存在或一个有效 MySQL 目标都未解析到时才读取历史配置。
- 同一个文件内所有格式正常的 JDBC URL 均参与检查，按 `host:port` 去重。
- 有效与损坏 URL 并存时继续使用有效目标，同时记录 WARN；不得回退历史文件掩盖标准配置问题。
- 两个文件均未提供有效目标时记录 FAIL，列出检查过的路径并提示管理员自行确认、测试 MySQL 地址。
- 仅解析主机和端口，不读取、不输出用户名、密码，不预解析 DNS。

## 数据流

1. `_parse_mysql_targets_from_file <path>` 扫描一个文件：
   - 忽略注释行；
   - 识别所有包含 `jdbc:mysql://` 的行；
   - 提取 `host:port`，无端口时使用 `3306`；
   - 有效目标追加到全局结果并去重；
   - 损坏行只记录警告和计数，不清除已经解析出的有效目标。
2. `parse_mysql_targets` 先解析标准文件：
   - 至少一个有效目标：选定标准文件，停止，不读取历史文件；
   - 文件不可读或零有效目标：清空中间结果，尝试历史文件。
3. 历史文件至少提供一个有效目标时选定历史文件；否则返回失败。

## 输出语义

- 成功时打印实际采用的配置文件和去重后的目标。
- 采用历史文件时打印 WARN，说明标准文件不存在或没有有效目标。
- 采用的文件存在损坏 URL 时记录独立 WARN，提示检查该文件配置；MySQL网络测试仍使用有效目标执行。
- 两个文件均失败时，`MYSQL_PARSE_ERROR` 同时包含两个文件路径和“请确认后自行测试 MySQL 地址”。

## 验收矩阵

1. 标准配置正常：只使用标准目标。
2. 标准配置多个有效 URL：全部提取并按 `host:port` 去重。
3. 标准配置有效与损坏 URL 并存：使用有效目标、输出 WARN、不读取历史配置。
4. 标准文件不存在：读取历史文件。
5. 标准文件存在但无 JDBC URL：读取历史文件。
6. 历史配置的 `spring.datasource.url` 和 `hive.mysql.url` 均为 `ta3:3306`：只生成 `ta3:3306`。
7. 注释中的 JDBC URL：忽略。
8. 两个文件均不存在或均无有效目标：FAIL并输出两个路径和人工测试提示。
